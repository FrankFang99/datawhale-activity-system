## 0. 现状问题（Frank 11:13 反馈的根因）

### 0.1 Frank 真实痛点
Frank 刚点击"志愿者审核通过"，**飞书 base 的 stage_task 表**有变化（`reviewStatus=APPROVED`），**但前端界面**：

### 0.2 根因（v1-v16.2 累计问题）

| 版本 | 关键改动 | 导致的问题 |
|---|---|---|
| v15 | 加 3 步进度（自核 → 审核 → 复核）+ 大按钮 | UI 复杂，按钮多 |
| v15.1 | 删 4 个 tag，3 步进度折叠 1 行 | 状态可见性下降 |
| **v16.2** | **删 3 步打勾整块**（Frank 反馈 8-24 08:32） | **状态完全不可见** |
| v16.2 | unlock 条件按 ownerType 区分 | 后端逻辑正确，但前端无反馈 |
| v16.2 | 后端 review 只在 REJECT/UNCERTAIN 发消息 | **APPROVE 不发消息** |

**核心问题**：v16.2 我按 Frank 8-24 08:32 反馈"删 3 步打勾整块 + 这里放子任务需要做的细项"——但**删了 3 步打勾后，状态可视化完全丢失**。"做什么"和"通过标准"是规范，不是状态。

### 0.3 与主流实践对比

| 主流系统 | 状态可视化 | 操作反馈 | 实时同步 |
|---|---|---|---|
| **飞书项目** | 卡片有"状态徽章"（待办/进行中/已完成/已审核）| 操作后立即 Toast + 操作记录 | 5 秒轮询 + WebSocket |

| **Asana** | 任务卡片进度环+操作人/时间 | Toast + 任务历史 | 实时 |
| **Notion** | 子任务 checkbox + 状态徽章 | Toast | 5 秒轮询 |
| **钉钉待办** | 任务状态 + 操作记录 | Toast + 推送 | WebSocket |
| **我们 v16.2** | ❌ 无状态徽章 | ❌ 无 Toast | ❌ 无轮询 |
| **我们 v16.3** | ✅ 状态徽章 + 状态行 + 操作历史 | ✅ Toast | ✅ 5 秒轮询 + 消息通知 |

## 1. v16.3 重新设计（4 大核心元素）

### 1.1 状态徽章（卡片右上角）

**位置**：每个子任务卡片标题行最右侧

**6 种状态**：
| 状态 | 颜色 | 标签 |
|---|---|---|
| ✓ 已完成 | 🟢 绿 #10B981 | step1Done + step2Done + step3Done |
| ⏳ 等待运营复核 | 🔵 蓝 #3370FF | step1Done + step2Done + !step3Done |
| ⏳ 等待志愿者审核 | 🟡 黄 #F59E0B | step1Done + !step2Done |
| ✗ 志愿者打回 | 🔴 红 #EF4444 | step2Rejected |
| ✗ 运营打回 | 🔴 红 #EF4444 | step3Rejected |
| ○ 待办 | ⚪ 灰 #9CA3AF | !step1Done |

### 1.2 状态行（卡片底部 · 颜色编码 3 步进度）

**位置**：凭证规范块下方

**格式**：
```
📊 当前进度：✓① 组织者自核 / ✓② 志愿者审核 / ✓③ 运营复核
   ─────────
· 组织者自核：2026/8/23 20:56:11
· 志愿者审核：通过（凭证完整）
· 运营复核：通过（复核通过）
```

**视觉效果**：
- 绿色左边框（状态颜色）
- 灰色背景 #F9FAFB
- ✓ = 绿 / ✗ = 红 / ○ = 灰

### 1.3 操作历史（时间线 · 谁/什么时候/做了什么）

**操作记录字段**（来自后端 sendMessage 触发）：
- `organizerSubmittedAt` → "组织者自核：{时间}"
- `reviewerId` + `reviewRemark` → "志愿者审核：通过/打回（{备注}）"
- `operatorReviewerId` + `operatorReviewRemark` → "运营复核：通过/打回（{备注}）"

### 1.4 实时同步（操作后立即 onRefresh + 消息通知）

**前端操作后立即刷新**（v16.3 Frank 11:50 反馈"不要 5 秒自动刷新"）：
- 删除了 v16.3 草稿阶段的 5 秒轮询（`setInterval` 全部清理）
- 操作后立即 `onRefresh()` 拉新数据（已有）
- 手动刷新：F5 / 重新进入活动页

**后端消息通知**（v16.3 新增）：
- `submit` (组织者自核) → 现有：发消息给志愿者 "请审核"
- `review APPROVE` → **v16.3 新增**：发消息给组织者 "志愿者已审核通过" + 通知所有运营 "等待运营复核"
- `review REJECT` → 现有：发消息给组织者 "请重新上传"
- `review UNCERTAIN` → 现有：发消息给所有运营 "请运营介入"
- `operatorReview APPROVE` → **v16.3 新增**：发消息给组织者 "本子任务全部完成" + 通知对接志愿者
- `operatorReview REJECT` → **v16.3 新增**：发消息给组织者 "请重新上传"

## 4. 主流多主体长流程参考（Frank 提到）

### 4.1 飞书项目（Teambition）
- 任务卡片：状态徽章 + 截止时间 + 操作人/头像
- 操作反馈：操作后立即 Toast + 站内信
- 实时同步：WebSocket 5 秒
- 阶段解锁：所有子任务完成 → 自动解锁下一阶段

### 4.2 钉钉审批
- 申请详情：审批人头像 + 时间 + 评论
- 操作反馈：审批通过/拒绝 → 通知所有相关人
- 实时同步：5 秒轮询
- 状态可视化：审批进度条 + 当前节点

### 4.3 Jira
- 工单卡片：状态列 + 操作记录 + 评论流
- 操作反馈：操作后状态列变化 + 通知
- 实时同步：WebSocket
- 子任务：每个子任务独立状态

### 4.4 Asana
- 任务卡片：进度环 + 操作人/时间
- 操作反馈：Toast + 任务历史
- 实时同步：实时
- 子任务：完成度可视化
